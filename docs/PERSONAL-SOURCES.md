# 个人电台源格式

在用户菜单的“个人电台源”页面添加网络地址或上传文件。网络地址可以是返回下列 JSON 的订阅接口，也可以是单个音频流或电台播放页。源与电台仅属于当前登录账号。

## JSON 文件和订阅

使用 UTF-8 编码，顶层必须是数组：

```json
[
  {
    "name": "CNR 中国之声",
    "categories": [["推荐电台"], ["国内电台", "央广"]],
    "urls": [
      "https://apppc.cnr.cn/national?cf=zgzs",
      "http://ngcdn001.cnr.cn/live/zgzs/index.m3u8"
    ]
  }
]
```

| 字段 | 说明 |
| --- | --- |
| `name` | 必填，电台名称；同源同名条目合并分类和备用地址 |
| `categories` | 可选，分类路径数组；每个内层数组是一条路径 |
| `urls` | 必填，地址数组；按顺序尝试，可以混合字符串和下面的对象 |

带请求头的地址推荐使用对象：

```json
{
  "url": "https://radio.example/live.m3u8",
  "headers": {
    "Referer": "https://radio.example/",
    "User-Agent": "Mozilla/5.0"
  }
}
```

仅允许 `User-Agent`、`Referer`、`Origin`、`Accept` 请求头。兼容旧列表中的 `-headers`（带引号、以 `\r\n` 分隔请求头）和 `-reuse 0` / `-reuse 1` 后缀；这些文本只作为数据解析，不执行命令，也不向 FFmpeg 透传任意选项。`reuse` 仅为导入兼容项，连接生命周期由服务端管理。

每个源最多 5 MiB、5000 个条目，每用户最多 32 个源。上传文件更新时选择“更新”并重新上传；网络源通过“更新”手动获取，不定时自动同步。同源同名电台保留 ID 和收藏，移除的电台同时移除收藏；拉取或解析失败不覆盖旧数据。

## 播放地址

| 类型 | 处理方式 |
| --- | --- |
| HTTP / HTTPS 连续音频、HLS、FLV | 检测响应类型并解码 |
| HTML / JSON / JSONP 播放页及接口 | 提取媒体地址，再获取媒体流；央广 `/national?cf=...` 按频道选择 |
| RTMP / RTMPS | 原生 RTMP 协议，经固定目标的连接转发 |
| RTSP / RTSPS | TCP 传输，经协议网关处理 |
| MMS / MMST / MMSH | MMS 尝试 MMST 后再尝试 MMSH |

个人电台通过服务器统一输出 MP3、128 kbps，浏览器无需支持旧协议。需要服务端 FFmpeg 和相应协议、解码器、MP3 编码器；Docker 已包含，二进制安装可通过 `MEOW_FFMPEG` 指定。RTMP 要求 FFmpeg 原生实现，不使用 librtmp 构建。部署关闭 `MEOW_RELAY` 时个人源播放和检测也不可用。

支持协议不保证每个历史网址仍在线。接口签名过期、地域限制、授权要求、站点改版或只有执行 JavaScript 才能得到音源的页面可能失败；不会执行第三方页面脚本。直接流没有扩展名时通过响应内容判断。

只访问公共 IP；拒绝私网、回环、URL 内的账号密码和不允许的端口。个人源支持 80、82、322、443、554、1024–65535 端口，重定向和 HLS 子资源同样检查。HTTP(S)/SOCKS5 出站代理沿用 `MEOW_PROXY`。

## 无效地址确认与删除

格式错误的地址在导入前集中展示，确认后才跳过这些地址继续导入；确认绑定待导入内容的快照，若在线订阅已变化，会重新展示地址，不直接清理新的记录。导入和更新成功后会逐条检测播放地址，也可手动点击“检测”。只有全部检测完成才展示失败列表，忙碌或缺少组件不会当成地址失效；可以停止检测、关闭、重试或选择要清理的地址。

例如电台 A 有 b、c、d，c 和 d 检测失败，对话框只列出 c、d。确认清理后保留 A、b 及已有收藏。只有最后一个地址也被清理时才移除电台及其收藏。网络失败可能只是暂时故障，关闭对话框不会清除任何地址。

删除单个电台、整个源或全部个人源均需确认，并同步删除对应个人收藏；系统电台收藏保持不变。检测结果仅可用于对应用户和源，内容已变化时需重新检测，不能用旧结果清除新的地址。
